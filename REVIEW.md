# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| #   | Where (function / line)                         | What is wrong                                                                                                                          | How you'd notice it (test, input, or symptom)                                                                                                             | How you fixed it                                                                                                                                                                     |
| --- | ----------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | Database calls across all routes                | Motor database calls (`find_one`, `count_documents`, etc.) were invoked without `await`.                                               | `RuntimeWarning: coroutine was never awaited`; endpoints returned unawaited coroutine objects or threw serialization errors.                              | Added `await` to all asynchronous database calls and used `.to_list()` on Motor cursors.                                                                                             |
| 2   | `GET /employees` pagination                     | Offset formula used `skip = page * page_size` instead of 1-indexed pagination.                                                         | `GET /employees?page=1` skipped the first 20 employees and returned page 2 results.                                                                       | Changed offset calculation to `skip = (page - 1) * page_size`.                                                                                                                       |
| 3   | Duration & Overtime helpers (`helpers.py`)      | Used standard Python `round()` which performs round-half-to-even (banker's rounding).                                                  | Boundary values like `2.255` rounded down to `2.25` instead of `2.26`, violating Rule R4.                                                                 | Implemented `round_half_up()` using `decimal.Decimal` with `ROUND_HALF_UP` quantization.                                                                                             |
| 4   | `POST /attendance/punch-in`                     | Checked existing punch-in via `find_one()` before `insert_one()` without a database-level uniqueness constraint.                       | Two simultaneous punch-in requests at the same millisecond both succeeded, causing duplicate attendance entries for the same date (Rule R1).              | Created a unique compound index on `("emp_code", 1), ("date", 1)` in MongoDB and caught `DuplicateKeyError` to return `409 Conflict`.                                                |
| 5   | `POST /attendance/punch-out`                    | Non-atomic read-then-update allowed race conditions on double punch-out, and lacked the 24-hour limit check.                           | Two concurrent punch-outs both returned 200, or a punch-out attempted 36 hours later was accepted.                                                        | Used atomic `find_one_and_update({"_id": record["_id"], "punch_out": None}, ...)` returning 409 if already closed, and validated `(punch_out - punch_in) <= 24 hours` returning 422. |
| 6   | Attendance date calculation (Rule R2)           | Attendance date naively parsed calendar day in UTC without accounting for shift attribution and cutoff.                                | An employee punching in after midnight for a late/night shift was credited to the wrong calendar day.                                                     | Implemented `get_attendance_date()` converting UTC instant to IST and mapping post-midnight hours before shift threshold back to the shift date.                                     |
| 7   | `GET /analytics/leaderboard/late`               | Ranked using simple index counter (`rank = i + 1`), ignoring standard competition ranking (Rule R8) and lacking secondary tie-breaker. | Tied employees received different consecutive ranks (e.g. 1, 2 instead of 1, 1), and ordering was non-deterministic.                                      | Implemented standard competition ranking (1224 ranking with ties sharing the same rank) with secondary sorting by `emp_code` ascending.                                              |
| 8   | `GET /analytics/departments/summary`            | Aggregation queried directly from `attendance_logs`, omitting department employees who had 0 logs during the month (Rule R9).          | Department headcount was underreported and attendance percentages were inflated when some employees were absent the entire month.                         | Derived total headcount from `db.employees` filtered by department, ensuring all active employees are counted regardless of log count.                                               |
| 9   | `GET /analytics/departments/{department}/trend` | Aggregation skipped days that had zero punches, producing gaps in the daily series and skewing the 7-day trailing average (Rule R10).  | Date timeline had missing days (e.g. weekends/holidays skipped); 7-day moving average was calculated over active days rather than actual 7 calendar days. | Generated a complete daily sequence for the month, filled missing days with zero counts, and computed the moving average across true 7-calendar-day sliding windows.                 |
| 10  | `PATCH /attendance/{emp_code}/{date}`           | Regularization updated record fields in place without appending an audit trail (Rule R6).                                              | Changes to status or punch timestamps left no trace of who modified the record or what previous values were.                                              | Appended audit records to the `history` array capturing `edited_by`, `edited_at`, and detailed `{from, to}` diffs for all modified fields.                                           |

---

### Non-defects Investigated

- **UTC storage vs IST computation:** Investigated whether instants in MongoDB should be stored in IST string format. Confirmed this is **not** a defect: storing UTC ISO datetimes in MongoDB and converting to epoch milliseconds on serialization adheres to Rule R1 and the OpenAPI specification.
- **Punch-in status restriction:** Investigated whether punch-in should allow `ABSENT`. Confirmed this is **not** a defect: Rule R1 strictly limits punch-in statuses to `PRESENT`, `WFH`, and `ON_DUTY`; `ABSENT` is a derived absence state when no punch exists, not a punchable status.
